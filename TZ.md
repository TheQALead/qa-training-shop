# Техническое Задание
## Проект: BugShop v0.1.0

---

## 1. Введение

### 1.1 Наименование проекта
**BugShop** — тренировочный полигон для QA-инженеров в виде интернет-магазина с намеренно встроенными багами.

### 1.2 Цель проекта
Создание учебной платформы для практики тестирования веб-приложений. Студенты учатся находить и документировать баги в условиях, приближённых к реальным проектам.

### 1.3 Целевая аудитория
- Студенты QA-курсов
- Начинающие тестировщики
- Преподаватели/наставники QA

---

## 2. Общее описание

### 2.1 Тип приложения
Веб-приложение (SPA) на базе Next.js 16 с App Router.

### 2.2 Технологический стек

| Категория | Технология |
|-----------|------------|
| Framework | Next.js 16 (App Router) |
| Язык | TypeScript 5 |
| Стилизация | Tailwind CSS 4 + shadcn/ui |
| База данных | SQLite (Prisma ORM) |
| State Management | Zustand |
| Уведомления | Sonner (toast) |
| Контейнеризация | Docker |

### 2.3 Роли пользователей

| Роль | Описание | Доступ |
|------|----------|--------|
| **Student** | Студент-тестировщик | Магазин, профиль, корзина, карты |
| **Visor** | Пользователь с расширенными правами (пасхалка) | + Кнопка удаления товаров |
| **Admin** | Администратор | Панель управления |

## 3. Функциональные требования

### 3.1 Модуль авторизации

#### 3.1.1 Вход в систему
- Поля: Логин, Пароль
- Валидация на клиенте и сервере
- После успешного входа — редирект в Магазин или Админку

#### 3.1.2 Выход из системы
- Кнопка "Выход" в шапке
- Очистка сессии и localStorage

#### 3.1.3 Вход в админку
- Секретная кнопка появляется при вводе "откройся" в скрытом поле
- Отдельная форма авторизации администратора

### 3.2 Модуль магазина

#### 3.2.1 Каталог товаров
- Отображение товаров по категориям
- Карточка товара: название, цена, остаток, фото
- Кнопка "В корзину" (недоступна при отсутствии товара)

#### 3.2.2 Корзина
- Иконка в шапке с количеством товаров и суммой
- Боковая панель со списком товаров
- Изменение количества (+/-)
- Удаление товара
- Отображение итоговой суммы
- Кнопка "Оплатить"

#### 3.2.3 Оформление заказа
- Модальное окно с анимацией (10 секунд)
- Проверка наличия карты
- Проверка остатков товаров
- Проверка баланса карты
- Списание средств и товаров

### 3.3 Модуль профиля

#### 3.3.1 Личные данные
- Отображение логина, роли, ФИО

#### 3.3.2 Управление картами
- Список привязанных карт
- Добавление новой карты (номер, владелец, срок, CVV)
- Удаление карты
- Отображение баланса

### 3.4 Модуль администратора

#### 3.4.1 Управление пользователями
- Создание пользователей (логин, пароль, роль, ФИО)
- Список пользователей
- Удаление пользователей

#### 3.4.2 Управление товарами
- Создание товаров (название, категория, цена, остаток, фото)
- Редактирование товаров
- Удаление товаров

#### 3.4.3 Управление картами
- Список всех карт пользователей
- Увеличение баланса карт (+10K, +50K, +100K)

#### 3.4.4 Управление багами
- Список всех багов с описаниями
- Включение/выключение багов для конкретного пользователя
- Массовое включение/выключение всех багов
- Отметка найденных багов

#### 3.4.5 Логи
- Лог входов пользователей (время, IP)
- Лог повышений прав до Visor

#### 3.4.6 Настройки
- Длительность PopUp уведомлений по типам:
  - Успешные (зелёные)
  - Ошибки (красные)
  - Предупреждения (жёлтые)
  - Информационные (синие)

## 4. Игровые баги (Intentional Bugs)

### 4.1 Список багов

| ID | Название | Описание | Severity | Как найти |
|----|----------|----------|----------|-----------|
| `charles-bug` | Charles Bug | Frontend добавляет "!" в конец пароля. Для входа нужно перехватить и удалить "!" через Charles | High | Использовать Charles Proxy |
| `power-rangers` | Power Rangers | Заголовок X-Role: "Red Power Ranger" даёт права Visor | Critical | Подменить заголовок в запросе |
| `cart-sum-bug` | Баг подсчёта суммы | При 2+ товарах: если сумма кратна 10 → +1000, иначе → +139 | High | Сравнить реальную и отображаемую сумму |
| `card-duplicate-digit` | Дублирование цифры карты | Frontend дублирует последнюю цифру номера | Medium | Проверить номер после сохранения |
| `card-typo-error` | Орфографическая ошибка | Сообщение "Не верно указаны даные" (пропущена "н") | Low | Создать некорректную карту |
| `fake-delete` | Фейковое удаление | Товар исчезает из DOM, но не из базы. Возвращается после перезагрузки | High | Удалить товар и обновить страницу |
| `missing-address` | Отсутствующий адрес | Заказ "отправлен по указанному адресу", хотя адрес никто не указывал | Medium | Оформить заказ |
| `card-owner-numbers` | Цифры в поле Владелец | Поле принимает цифры, хотя должно только буквы | Low | Ввести цифры в поле Владелец |
| `uncomfortable-buttons` | Неудобное расположение кнопок | Кнопка "Выход" рядом с "Корзиной" — можно случайно нажать | Low | Визуальный осмотр шапки |

### 4.2 Механизм багов
- Каждый баг имеет ID, название, описание, категорию, severity
- Баги хранятся в таблице `Bug` в БД
- Связь с пользователями через таблицу `UserBug`
- Администратор может включать/выключать баги для каждого пользователя

| DELETE | `/api/cart` | Удалить товар |

|-------|----------|----------|
| GET | `/api/cards` | Список карт |

| DELETE | `/api/cards` | Удалить карту |

### 5.6 Заказы

| Метод | Endpoint | Описание |
|-------|----------|----------|

### 5.7 Администрирование

| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/api/admin` | Данные для админки |

## 6. Структура базы данных

### 6.1 ER-диаграмма (описание таблиц)

```
User ──< CartItem >── Product
  │
  ├──< Card
  │
  ├──< UserBug >── Bug
  │
  └──< LoginLog

Admin
Settings
VisorLog
```

### 6.2 Таблицы

#### User
| Поле | Тип | Описание |
|------|-----|----------|
| id | String | UUID |
| login | String | Уникальный логин |
| password | String | Пароль |
| role | Enum | Student / Visor |
| fullName | String? | ФИО |
| createdAt | DateTime | Дата создания |

#### Product
| Поле | Тип | Описание |
|------|-----|----------|
| id | String | UUID |
| name | String | Название |
| category | String | Категория |
| price | Int | Цена в рублях |
| stock | Int | Остаток на складе |
| imageUrl | String? | URL изображения |

#### CartItem
| Поле | Тип | Описание |
|------|-----|----------|
| id | String | UUID |
| userId | String | FK → User |
| productId | String | FK → Product |
| quantity | Int | Количество |

#### Card
| Поле | Тип | Описание |
|------|-----|----------|
| id | String | UUID |
| userId | String | FK → User |
| owner | String | Владелец |
| number | String | Номер карты |
| date | String | Срок действия |
| cvv | String | CVV |
| balance | Int | Баланс |
| isBuggy | Boolean | Бажная карта |

#### Bug
| Поле | Тип | Описание |
|------|-----|----------|
| id | String | ID бага |
| name | String | Название |
| description | String | Описание |
| category | String | Категория |
| defaultEnabled | Boolean | Включен по умолчанию |

#### UserBug
| Поле | Тип | Описание |
|------|-----|----------|
| id | String | UUID |
| userId | String | FK → User |
| bugId | String | FK → Bug |
| enabled | Boolean | Включен для пользователя |
| found | Boolean | Найден студентом |

## 10. Пасхалки

### 10.1 Вход в админку
В поле с placeholder "Hsss-ah-sssh-hiss..." ввести слово "откройся" → появится кнопка "🐍 Тайная комната"

### 10.2 Power Rangers
При любом запросе отправляется заголовок `X-Role: Green Power Ranger`. Если заменить на `Red Power Ranger` — пользователь получает права Visor.

## 11. Ограничения и допущения

1. Приложение учебное, не для production
2. Хранение паролей в открытом виде (для обучения Charles)
3. Нет реальной оплаты — виртуальный баланс карт
4. Нет доставки — учебный сценарий
5. localStorage для хранения сессии (не JWT)
