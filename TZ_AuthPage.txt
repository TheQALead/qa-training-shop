1. ОБЩАЯ ИНФОРМАЦИЯ
--------------------------------------------------------------------------------

Страница авторизации — точка входа в приложение BugShop для всех пользователей.

Путь: /
Вид доступен: неавторизованным пользователям

Пользователи:
  - Student (студент)
  - Visor (студент с повышенными правами)
  - Admin (администратор)


2. ЭЛЕМЕНТЫ СТРАНИЦЫ
--------------------------------------------------------------------------------

2.1. Логотип и название

2.2. Карточка формы входа

2.4. Поле "Пароль"

3. ЛОГИКА АВТОРИЗАЦИИ
--------------------------------------------------------------------------------

3.1. Базовый сценарий (без багов)
    1. Пользователь вводит логин и пароль
    2. При потере фокуса с поля "Логин" → запрос GET /api/bugs/status?login={login}
    3. При нажатии "Войти" → POST /api/auth/login с данными
    4. Если успешно → редирект в магазин (ShopView)
    5. Если ошибка → Toast с текстом ошибки

3.2. Заголовки запроса авторизации
    - Content-Type: application/json
    - X-Role: "Green Power Ranger" (по умолчанию)

3.3. Тело запроса
    {
      "login": "введённый_логин",
      "password": "введённый_пароль"
    }

3.4. Успешный ответ (200)
    {
      "success": true,
      "token": "base64_токен",
      "user": {
        "id": "...",
        "login": "...",
        "role": "Student|Visor",
        "fullName": "..."
      },
      "isAdmin": false
    }

3.5. Ошибка авторизации (401)
    {
      "error": "Пользователь не найден" | "Неверный пароль"
    }


4. БАГ: CHARLES BUG
--------------------------------------------------------------------------------

ID: charles-bug
Название: Charles Bug
Категория: Авторизация
Severity: High

4.1. Условие активации
    - Баг включен для конкретного пользователя (charles-bug: ON)
    - По умолчанию: ВЫКЛЮЧЕН для новых пользователей

4.2. Проявление бага
    - Frontend автоматически добавляет символ "!" в конец пароля
    - Пароль "pass123" отправляется как "pass123!"
    - Консоль браузера содержит подсказки:
      * "🔍 [DEBUG] Original password: pass123"
      * "🔍 [DEBUG] Password sent to server: pass123!"
      * "🔍 [DEBUG] Charles bug enabled: true"
      * "🔍 [DEBUG] Hint: Notice the '!' at the end? Check Charles..."

4.3. Поведение сервера при активном баге
    - Если пароль заканчивается на "!" → сервер ВОЗВРАЩАЕТ ОШИБКУ (не пускает)
    - Если пароль без "!" (исправлен через Charles) → сервер ПУСКАЕТ

4.4. Как найти баг
    1. Включить Charles Bug для пользователя в админке
    2. Попробовать войти с правильным паролем → ошибка
    3. Открыть DevTools Console → увидеть подсказку
    4. Перехватить запрос в Charles Proxy
    5. Удалить "!" из пароля в перехваченном запросе
    6. Запрос успешно проходит → вход выполнен

4.5. Решение бага
    - Использовать Charles Proxy / Fiddler для модификации запроса
    - Удалить символ "!" из пароля перед отправкой на сервер


5. ПАСХАЛКА: POWER RANGERS
--------------------------------------------------------------------------------

ID: power-rangers
Название: Power Rangers Easter Egg
Категория: Пасхалки
Severity: Critical

5.1. Условие активации
    - Баг включен для пользователя (по умолчанию: ON)
    - Заголовок X-Role: "Red Power Ranger" (вместо "Green Power Ranger")

5.2. Проявление
    - Пользователь с ролью Student получает роль Visor
    - Toast сообщение: "🎉 Power Ranger mode activated!"
    - Запись в логах пасхалок (раздел "Пасхалки" в админке)

5.3. Как найти
    - Перехватить запрос авторизации
    - Изменить заголовок X-Role на "Red Power Ranger"
    - Войти как обычный студент → получить права Visor


6. СОХРАНЕНИЕ АВТОРИЗАЦИИ
--------------------------------------------------------------------------------

6.1. Token сохраняется в localStorage
    - Ключ: "bug-shop"
    - Содержит: user, token, isAdmin, isAuthenticated

6.2. При обновлении страницы
    - Проверяется наличие токена в localStorage
    - GET /api/auth/verify с заголовком Authorization: Bearer {token}
    - Если валиден → авторизация восстановлена
    - Если невалиден → logout, возврат на страницу входа
